## Findings

### Aggregate / cross-story

1. **`SettingsScreen.handleAccept` embeds full business logic (network validation, secure-store write, status state machine) directly in the screen**, diverging from the epic's own declared "screens hold no business logic" decision (`epic-1-context.md`) and from the hook-extraction pattern Story 1.6 later established (`useTracerBullet`). [`src/screens/SettingsScreen.tsx:83-124`] — **disposition: defer** (propose as a refactor action item). **Process lesson:** this convention isn't lint-enforced (unlike the `components/**` import boundary, which is), so nothing caught the drift; only a cross-story retro surfaces it.
2. **Three different, non-communicating "is this async result still valid" mechanisms exist across two stories**: `SettingsScreen`'s `isMountedRef` (guards `handleAccept`), a separate closured `cancelled` boolean in the same file (guards only the hydration effect), and `useTracerBullet`'s generation-counter (added during this session's Story 1.6 code review). [`src/screens/SettingsScreen.tsx:49-54,59-81`; `src/features/tracerBullet/useTracerBullet.ts:37,60`] — **disposition: defer** (process lesson: introduce one shared convention/hook before a third story reinvents it again).
3. **Hydration-vs-save race in `SettingsScreen`**: the mount-time secret-hydration effect's only staleness guard fires on unmount, not on "superseded by a newer save" — if it resolves after `handleAccept` has already saved a new secret, it can overwrite `savedSecret` with the pre-save value, so a subsequent "Descartar" reverts to stale data. Narrow timing window (a keychain read normally resolves well before a user can retype and tap Accept). [`src/screens/SettingsScreen.tsx:59-81` vs. `111-123`] — **disposition: defer**, bundle with item 1's refactor.
4. **Navigating back from Settings while a connection save is in flight silently drops the result** with no user feedback — `handleAccept` checks `isMountedRef.current` after `await validateConnection(...)` and returns without writing or erroring if the screen was already left (safe — no zombie write — but no feedback either). [`src/screens/SettingsScreen.tsx:83-99,176-184`] — **disposition: accept as-is**, same class as this story's already-logged deferred UX-polish items (`deferred-work.md`, spec-1-5 section); not new information, no AC requires it.
5. **Missing test for `useTracerBullet`'s new staleness guard**: this session's Story 1.6 code-review pass added a generation-counter to `submit()` so a `reset()` during an in-flight request is ignored, but no test exercises "reset() while submit() is still pending" — a regression here (removing or inverting the guard) would pass every existing test. [`src/features/tracerBullet/useTracerBullet.ts:57-106`; `useTracerBullet.test.ts`] — **disposition: fix now** (cheap, protects a just-written guard).
6. **Stale doc comment** in `theme/colors.ts`: says `conchiColors` is "Currently consumed by `ConchiBubble.tsx`'s SVG placeholder" — `ConchiBubble` has rendered the real `conchi-idle.png` `<Image>` since a Story 1.4 follow-up commit (`deferred-work.md`'s "RESOLVED" entry). [`src/theme/colors.ts:73-76`] — **disposition: fix now** (one-line comment correction, no behavior change).
7. **`KeyboardAvoidingView` gap recurs across two of the three text-input surfaces built this epic** — deferred individually for `SettingsScreen` (Story 1.5, `deferred-work.md`) and raised again for `TracerBulletModal` during Story 1.6's own code review (dismissed there as out of scope for a throwaway feature). Same gap, two stories, never addressed. [`deferred-work.md:145-147`; `src/components/TracerBulletModal.tsx`] — **disposition: defer** as a named epic-level pattern — worth a shared form-screen convention before Epic 2 adds more text-input surfaces, rather than re-deferring per-story indefinitely.
8. **Accessibility semantics gaps** (`accessibilityRole="header"`/`"radio"`, decorative SVGs not marked non-accessible) recur across Stories 1.4 and 1.5 — already individually logged in `deferred-work.md`. Reconfirmed still-open; **disposition: accept as already-tracked**, no new item (avoid duplicate tracking).
9. **Hardcoded Catalan strings with no i18n module** recur across Stories 1.4, 1.5, and 1.6 — already logged in `deferred-work.md` each time. This is an **accepted deviation**, not a defect: the PRD explicitly scopes the Idioma toggle out of V1 (Catalan-only, deferred to V1.1), so no i18n scaffolding is expected yet.
10. **AD-6 (MinIO rejection) left no residue**: `self-hosting/` was fully removed, no MinIO references remain anywhere in `docs/` — confirms the Story 1.2 revert was executed cleanly, consistent with `ARCHITECTURE-SPINE.md`'s AD-17. No action needed — recorded as a confirmed-clean check, not a gap.
11. **Feature-sliced architecture boundary (AD-2) holds**: `.eslintrc.js`'s `no-restricted-imports` override list is scoped correctly (only `screens/`, `lib/`, `features/`, `store/`, `App.tsx`, and `navigation/index.tsx` — the composition roots — are exempted; `components/**` and `BottomNavBar.tsx` remain restricted). Only one `eslint-disable` exists in the whole `src/` tree, unrelated to this boundary and documented. No action needed.
