- (constraint) Sources loaded: PRD (prd-conchi-2026-08-20/prd.md), UX Design System (DESIGN.md), Experience Spec (EXPERIENCE.md). These drive all invariants.
- (decision) Platform: bare React Native. Expo SDK packages (expo-notifications, expo-camera, expo-file-system, expo-secure-store, etc.) used as libraries. Binds: all. Prevents: Expo managed workflow, which blocks native widget extension targets (WidgetKit, App Widget). Rule: no Expo managed workflow; prebuild/bare only.
- (decision) Code organisation: feature-sliced business logic + atomic component library. Boundary rule: components/ is Zustand-free and n8n-free — presentational only. Feature logic lives in features/{feature}/use*.ts hooks + store slices. Screens are thin orchestrators. Zustand slices live inside feature folders; store/index.ts aggregates and re-exports only. Prevents: store becoming a global dumping ground; components accumulating API/state coupling.
- (decision) Transport protocol: app POSTs to n8n webhook (immediate 200 ack). n8n pushes result back via FCM combined message (notification + data payload). Single FCM pipe handles: round-trip results (foreground → Confirmation Card, background → push notification + deep link) and invoice notifications (unknown/known sender). Message type discriminated by data.type field. expo-notifications abstracts FCM/APNs. Prevents: separate SSE relay infrastructure; separate notification and result-delivery systems.
- (decision) Analytics Endpoint: app sends structured JSON filter params {from, to, category, subcategory, context} to n8n webhook. n8n Postgres node executes ONE fixed parameterised SQL query using nullable params. n8n is a 3-node relay (Webhook → Postgres → Respond) with no custom code. SQL and schema stay server-side. Prevents: app-to-DB schema coupling; dynamic SQL construction on client.
- (decision) File storage for app-uploaded files: MinIO (self-hosted, S3-compatible, Docker container on existing VPS). Upload path: app → n8n webhook → MinIO S3 node → URL stored in DB. App reads files directly from MinIO URL at view time. Prevents: routing file reads through n8n on every view; using Google Drive for mobile uploads (OAuth complexity, no portfolio signal).
- (decision) Local persistence: MMKV (react-native-mmkv) for all local storage — offline queue, settings, active context, FCM device token. Synchronous reads prevent Drum Roller flicker. Categories: fetched from n8n on first launch, cached in MMKV, refreshed only on explicit user action in Settings. Contexts: created inside the app (source of truth is the app + DB); local cache updated optimistically on create/archive/delete — no background refresh needed (single user, app is the only creator). Prevents: AsyncStorage async reads causing picker flicker; unnecessary network calls on foreground.
- (decision) Animations: React Native Reanimated + Gesture Handler included. Required by: FAB radial fan arc, swipe-to-reveal gesture-driven rows, post-log cascade stagger, Confirmation Card slide-up. Standard Animated API insufficient for gesture-driven animations. PRD conditional approval met.
- (decision) n8n auth: shared webhook secret. App sends Authorization: Bearer <secret> header on all n8n requests. Secret stored in expo-secure-store (device secure enclave, not MMKV). Settings connection fields: webhook base URL + auth secret. Prevents: unauthenticated n8n webhook access; storing secrets in MMKV (plain key-value, not encrypted).
- (decision) E2E testing: Detox (industry standard for React Native, portfolio signal). Tests cover golden-path journeys UJ-1 through UJ-7. Animations disabled in test builds via environment flag to prevent flakiness. Setup done as part of architecture skeleton before first feature story. Prevents: Maestro (less recruiter-recognisable); untested golden paths.
- (decision) Navigation: React Navigation (community standard, deep link support, TypeScript route param types). 3 main screens + modal/sheet surfaces. Deep links handle notification tap-to-card routing (Confirmation Card, Invoice Review Card). Prevents: Expo Router (Expo-specific abstraction, overkill for 3-screen app in bare RN).
- (decision) Min OS: iOS 16 (required for interactive widget AppIntents enabling text submission without opening app), Android API 26 / Android 8.0 (modern App Widget interactions, ~95% active device coverage).
- (decision) FCM token registration: on app startup, app POSTs FCM device token to dedicated n8n endpoint. n8n upserts to device_tokens table in PostgreSQL. Required for invoice notification workflows that fire without an app request. Token refreshed automatically via expo-notifications token rotation callback.
- (decision) Package manager: pnpm. Prevents: npm/yarn usage anywhere in the project (scripts, CI, docs). Rule: all install/run commands use pnpm; lockfile is pnpm-lock.yaml.
- (decision) CI/CD: GitHub Actions. PR gate: lint + type check + unit + component + Detox E2E tests (Android emulator via reactivecircus/android-emulator-runner). Merge to main: Android APK built and distributed via Firebase App Distribution (invite-only, Marc's email only). No iOS build in CI pipeline — iOS tested locally by Marc. No Google Play / App Store submission. APK signing key, Firebase credentials, n8n secrets, MinIO credentials all stored in GitHub Secrets — never committed to repo. Prevents: secrets in repo; public APK distribution.
- (constraint) Security — public repo: all credentials (Firebase, n8n webhook secret, MinIO, Android signing keystore, FCM server key) live exclusively in GitHub Secrets and device secure storage (expo-secure-store). .env files gitignored. No hardcoded URLs or tokens in source. Self-hosting guide documents where credentials go without exposing Marc's own values. n8n webhook auth secret prevents unauthorised access to Marc's server from anyone who reads the public repo.
- (decision) Repo documentation: self-hosting guide committed to repo covering n8n instance setup, Conchita configuration, DB schema, MinIO setup, app Settings connection fields — written for a technically capable audience who wants to fork and run their own instance.
- (decision) Documentation tooling: Docusaurus (/docs folder, GitHub Pages, covers self-hosting guide + architecture overview + project intro) + Storybook for React Native (@storybook/react-native with react-native-web output for GitHub Pages hosting). Stories written alongside components in .stories.tsx files. Both auto-deployed to GitHub Pages via GitHub Actions on merge to main. Prevents: documentation living only in the repo README; components undocumented in isolation.
